# routeros_ip_reverse_proxy (Resource)
Reverse proxy rules (`/ip/reverse-proxy`): each rule forwards the HTTPS requests for one host name to an HTTP server. The listener is the `reverse-proxy` service in `/ip/service` (see `routeros_ip_service`), its port is open only while at least one enabled rule exists.

## Example Usage
```terraform
# The listener: port and default certificate of the reverse-proxy service.
resource "routeros_ip_service" "reverse_proxy" {
  numbers     = "reverse-proxy"
  port        = 443
  certificate = "wildcard.example.com"
  disabled    = false
}

resource "routeros_ip_reverse_proxy" "app" {
  sni        = "app.example.com"
  ip_address = "192.0.2.10"
  port       = 8080
  comment    = "app container"
}
```

## Schema

### Required

- `ip_address` (String) IPv4 or IPv6 address of the server the requests are forwarded to (always as plain HTTP).
- `port` (Number) TCP port of the server. The router always connects with plain HTTP, also when the port is 443.
- `sni` (String) Host name the rule serves. It is compared with the SNI the client sends and must match it exactly; a wildcard such as `*.example.com` matches nothing.

### Optional

- `certificate` (String) Certificate the router presents to clients of this rule. With `none`, the certificate of the `reverse-proxy` service in /ip/service is used; if that is also `none`, the TLS handshake fails.
- `comment` (String)
- `disabled` (Boolean)
- `vrf` (String) The VRF table this resource operates on.

### Read-Only

- `dynamic` (Boolean) Configuration item created by software, not by management interface. It is not exported, and cannot be directly modified.
- `id` (String) The ID of this resource.
